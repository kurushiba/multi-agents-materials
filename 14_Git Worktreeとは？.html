GIT LIMITATION従来の並行作業における課題

  • 1リポジトリ = 1作業ディレクトリ
    Gitの標準的な運用では、1つのクローンされたリポジトリに対して作業できるフォルダは物理的に1つだけという制限があります。
  • ブランチ切り替え時の手間
    書きかけのコードがある状態で別の緊急タスクを頼まれると、`git stash` を使って一旦変更を退避し、ブランチを切り替える必要があります。
  • 退避忘れやコンフリクトのリスク
    退避や復元の手順は地味に手間で、退避を忘れて別のブランチで作業してしまうと、思わぬ衝突や書き換えが起こり得ます。

GIT WORKTREEGit Worktreeによる新しい解決策

  • 独立した作業ディレクトリを複数作成
    1つのGitリポジトリ（内部データ）を共有しながら、異なるブランチをチェックアウトした作業ディレクトリを物理的に複数作れる機能です。
  • `stash` 無しで並行開発
    元のディレクトリを変更することなく、別ブランチの作業スペースを隣のフォルダに作れるため、変更の退避やブランチの切り替えが一切不要になります。
  • 軽量かつ瞬時の立ち上げ
    `git clone` で丸ごと複製するのとは異なり、Gitの管理メタデータは共通のものを参照するため、一瞬で超軽量な追加作業ディレクトリを作成できます。

AGENT CONFLICT複数AIの同時稼働が引き起こす衝突

  • AIはファイルを直接書き換える
    AIエージェントは、指示された作業ディレクトリの中のコードを自動で読み込み、編集・保存してタスクを進めます。
  • 同一フォルダでの並行作業の崩壊
    同じ作業ディレクトリで複数のAIを同時に動かすと、お互いが気づかないうちに同じファイルを上書きしてしまいます。
  • 変更の「上書き消滅」が発生
    AI 1が編集した結果を、AI 2が古い状態を基にした編集内容で上書き保存し、成果物が台無しになる危険性があります。

PHYSICAL ISOLATIONWorktreeで物理的な競合を防ぐ

  • 物理フォルダをAIごとに切り分ける
    各AIエージェントに対して、Git Worktreeで生成した個別の作業ディレクトリをそれぞれ割り当てます。
  • ファイルの完全な分離による衝突回避
    物理的に書き込む場所が別フォルダとして切り離されるため、エージェント同士が同じファイルを書き換え合う事故が100%防げます。
  • 自律並行マルチエージェントの実現
    人間が仲介してファイルの退避を指示することなく、複数のAIが並行して異なるタスクを安全に高速開発できます。

BEST PRACTICEAI並列開発を成功させる4つのルール

  • 人間側での「タスクの事前切り分け」
    Worktreeが防ぐのは「作業中」の衝突だけ。最終的にブランチを合流（マージ）する際、コンフリクトは起こり得ます。
  • コンフリクトを回避するタスク設計
    AIに並列で作業を依頼する前に、人間がマージしやすさを考慮してタスク同士の結合度を下げておく必要があります。
  • ルールに沿った自律プロセスの制御
    以下の4つのコツを理解し、AIエージェントのパフォーマンスと開発効率を最大限に引き出しましょう。
01
📂 触るファイルで分ける
「機能」単位ではなく「日本語と英語の翻訳ファイル」のように触る物理ファイルを完全に分ける。
02
➡️ 依存関係は直列にする
DBテーブル追加の後にAPI実装など、前提の必要な作業は並行せず順番に行う。
03
🔒 ロックファイルの競合回避

SUMMARY効率的なAI並列開発の鉄則

  • Git Worktreeの標準活用
    1つのリポジトリをベースにして、異なるブランチを持つ独立した作業ディレクトリを軽量・高速に生成・管理します。

    各AIに個別のWorktreeディレクトリを割り当て、作業中のファイル上書き事故（排他制御の失敗）を防ぎます。
  • 人間による適切なタスクの設計
    物理的なファイル分け、依存関係の直列化、ロックファイルの考慮をあらかじめ人間が計画することで、マージまでスムーズに進めます。
