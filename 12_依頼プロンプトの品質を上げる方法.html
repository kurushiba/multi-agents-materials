OVERVIEW依頼プロンプトの品質を上げる3つのアプローチ

  • 可変である「目的」の制御
    サブエージェント呼び出しのつど、メインAIが自動で組み立てて手渡す可変のパラメータが「目的」です。
  • 直接編集できないという制約
    メインAIの自律生成であるため、人間が直接プロンプトを書き込んで中身をコントロールすることはできません。
  • 認知プロセスへの間接的介入
    メインのAIの意思決定メカニズム（定義・環境・初期指示）に働きかけることで、生成されるプロンプトの質を向上させます。

LEVER 01レバー①: description によるブレの防止

  • メインAIの唯一の手がかり
    サブエージェント定義ファイルの description は、メインAIが「何をする専門家か」を判断するほぼ唯一のソースです。
  • 具体的であるほど目的がブレない
    アクションやアウトプットが明確に書いてあれば、メインAIは守備範囲からはみ出さない、正確な目的を生成します。
  • 曖昧さがもたらす失敗
    記述が曖昧だと、無関係な仕事を押し付けたり、本来任せるべき場面で呼び出されなかったりするエラーが起きます。
❌ 曖昧な定義
目的のブレ・不安定
🤔 曖昧な役割 何でもこなせるように見え、多すぎるタスクを押し付けてしまう
⚠️ 誤った呼び出し 不適切な状況で呼び出され、予算とトークンを無駄遣いする
✅ 具体的な定義
専門特化・安定稼働
🎯 アクションと成果の明確化 やること、成果物が明確なため、正確にタスクを生成できる
🛡️ 範囲の限定 想定外の仕事をシャットアウトし、確実に機能する

LEVER 01description 応用：積極性とトリガーワード

  • 積極起動のコントロール
    「指示なしで自動起動する」積極性は有用ですが、どんなサブエージェントにも一律で付与してはいけません。
  • ロールの性質で使い分ける
    コード変更監視などの安全検査は「積極起動」を設定。高コストなリサーチやデバッグは「手動起動のみ」とします。
  • トリガーワードを先回りして仕込む
    人間の口癖（例：「PRレビュー」）を description に含めることで、メインAIが必要な場面を認識しやすくします。
🟢 積極起動 (自動化向き)
コードレビューや型検査など、変更を監視して即時フィードバックが必要なロール。
AUTO START
🟡 手動起動 (コスト保護向き)
広範囲なリサーチやコマンドデバッグなど、APIコストや時間がかかるロール。
MANUAL RUN
🗣️ トリガーワード設計 ユーザーの言葉を先回りして description に仕込む
「このPRをレビューして」 ➔ 一致 ➔ "PRレビューに使用する"

LEVER 02レバー②: CLAUDE.md による制御

  • プロジェクト固有ルールの設定
    CLAUDE.md は起動時に毎回自動で読み込まれる設定ファイル。ここにサブエージェントの呼び出し規則を記述します。
  • 自動起動パイプラインの構築
    「完了報告前に必ず reviewer を自動起動し判定を得ること」のように書くことで、人間が指示せずとも自律稼働します。
  • テンプレート制限の強制導入
    依頼時に「目的」「出力」「ツール」「境界」の見出し使用を義務付けることで、生成される指示の品質を物理的に高めます。

LEVER 03レバー③: 人間からの初期プロンプトの具体性

❌ 曖昧な初期指示の例
「適当にバグを直してテストを書いておいて」

⚠️ メインAIは対象範囲やルールを自分で推測するしかなく、不完全な目的を持ったままサブエージェントへ依頼が渡ってしまう。
✅ 具体的な初期指示の例
「src/routes/user.ts に対する型定義のエラーを修正し、完了条件として npm run test:user がグリーンになることを検証してください。なお、データベースへの実際の書き込みはモックし、実際の書き込みテストは『やらないこと』としてください。」
💡
目的の材料を直接渡す: 「対象ファイル」「完了条件」「やらないこと（非目標）」を人間が明示することで、メインAIは推測に頼ることなく、高品質な目的をそのままクリーンにサブエージェントへマッピングできます。

SUMMARYプロンプト品質を極める3要素の連携

  • ブレを許さない description
    役割を専門的に具体化し、不要な仕事の割り当てや曖昧な目的生成をシャットアウトします。
  • タイミングと形式を決める CLAUDE.md
    自動起動パイプラインを定義し、テンプレート制限で見出しの義務化（目的の解像度アップ）を強制します。
  • 正確な材料をインプットする初期指示
    対象・完了条件・やらないことを人間から明示し、推測によるエラーや無駄な探索をほぼゼロにします。
