OVERVIEWシステムプロンプトの役割と3つの固定要素

  • 可変である「目的」の分離
    依頼ごとに変化する「目的」は、メインAIが都度生成する依頼プロンプト（前回学習）で渡す。
  • 固定である3つの要素
    「出力フォーマット」「ツールや情報源」「タスクの境界」は、タスクによらず基本的に固定のためシステムプロンプトに定義する。
  • 二重の構成構造
    設定情報となる「YAMLフロントマター」と、自然言語で指示する「Markdown本文」の2つから成る。

MARKDOWN 01本文の設計①：役割定義 & 観点チェックリスト

  • 役割の一文定義（専門性の決定）
    「あなたは〇〇に特化したスペシャリストである」と明記。何者であるかを定義し、AIの全判断の土台とする。
  • 観点チェックリストによる抜け漏れ防止
    評価すべき基準をリストにして並べ、必ず上から順にチェックすることを義務付ける（例: メモリリークの確認等）。
  • 「肯定形」のタスク境界
    「必ず実行すべきこと」を内側から縛ることで、タスク境界の半分を定義する（残り半分は否定形の境界）。

MARKDOWN 02本文の設計②：出力構造の制限 & 否定形の境界

  • 出力フォーマットの厳格な指定
    「最終的な返却値は必ず次の構造のみに従うこと。前置きや挨拶は一切排除せよ」と指定し、親AIが解釈しやすくする。
  • 否定形のタスク境界による暴走抑止
    「自分で書いたコードをローカルファイルに直接書き込んではならない」等、明確に「やってはいけない」を指示する。
  • 肯定・否定が揃って境界が定まる
    「やるべきこと（肯定形）」と「してはならないこと（否定形）」の両側から規定することで、スコープを完全に確定する。

FRONT MATTERYAMLフロントマターによるツール権限の制限

  • description による起動の制御
    サブエージェントの役割記述。メインAIが「何をする専門家か」を判断し、適切な時に起動するために使われる。
  • tools フィールドでの権限の指定
    サブエージェントが使用できるツールを制限し、範囲外のアクションを物理的に制限する（暴走を防ぐ最強の防御壁）。
  • 例: 読み取り専用エージェントの作成
    `tools: [Read, Grep, Glob]` に絞り、`Write` や `Edit` などの破壊的ツールへのアクセスをあらかじめ外しておく。
YAML Configuration
tools: [Read, Grep, Glob]
🟢 許可ツール（アクセス可）
Read Grep Glob
読み取りに必要な権限のみ通過を許可
🔴 遮断ツール（実行不可）
Write Edit
書き換え権限を物理的に遮断して暴走を防止

CONSTRAINT二段構えの制約設計：ソフト指示とハード遮断

  • プロンプト指示（ソフトな制約）の限界
    いくら本文で「ファイルを編集するな」と指示しても、AIが推論時にルールを忘れてしまい、書き換えてしまう事故が起こる。
  • toolsによる「ハードな物理遮断」
    実行環境そのものからツールの権限を取り除くことで、エージェントがルールを忘れても物理的に実行できない状態にする。
  • 信頼できるシステムプロンプトの秘訣
    本文のソフトな制約（指示）を、フロントマターのハードな物理遮断（tools制限）で裏打ちする二段構えが必要。

SUMMARY信頼できるシステムプロンプトの設計方針

  • 役割の明示と肯定的な境界
    専門ロールを冒頭で一文定義し、観点チェックリストで「やるべきこと（肯定形）」の境界を固定する。
  • 厳格な出力フォーマットと否定の境界
    親AIが扱える形に出力を絞り、否定形の境界で「やってはいけないこと」を明記する。
  • 物理的遮断による裏打ち
    本文の禁止指示は、フロントマターの `tools` 制限で確実に物理遮断する。これによって安全で完璧なエージェントが稼働する。
