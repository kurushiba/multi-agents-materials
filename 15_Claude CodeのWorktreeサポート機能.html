NATIVE SUPPORTネイティブWorktree機能の登場

  • 手動Gitコマンドの自動集約
    ディレクトリ作成、ブランチ切り出し、環境移動などの手動操作を一切行うことなく、コマンド一発で安全な隔離環境を起動できます。
  • 用途に合わせた2つのアプローチ
    開発者自身の作業を隔離する「人間向けコマンド」と、自動起動されるサブエージェントに適用する「AI向け設定」が用意されています。
  • コンフリクトゼロの開発体験
    複数AIエージェントの同時並行開発において、作業中の環境干渉を防ぐ「絶対のセキュリティ境界」を構築・制御します。
For Humans
🖥️ claude --worktree
開発者自身が別の検証やバグ修正を始める際に、一発で隔離スペースを立ち上げるためのCLIコマンド。
AND
For Agents
⚙️ isolation: worktree
サブエージェント定義（YAML）に指定する設定。起動のたびに完全に個別のWorktreeが自動でアサインされます。

HUMAN CLI人間が作業を隔離するコマンド

  • コマンド一発でセットアップ完了
    `claude --worktree `（短縮形 `-w`）を叩くだけで、専用ブランチの作成からチェックアウト、Claude Code起動までが瞬時に完了します。
  • 専用ブランチとディレクトリの作成
    裏側で `.claude/worktrees//` フォルダが作成され、最新の main から切り出された `worktree-` ブランチが割り当てられます。
  • 名前省略によるランダム生成
    名前を省略して起動すると `bright-running-fox` のような名前がランダムに割り振られ、使い捨てのコード実験を素早く開始できます。
$ claude --worktree my-feature

PR REVIEW他人のPRを安全に手元で検証

  • 他人のPRを手間なくローカル起動
    `claude --worktree "#1234"` のようにプルリクエスト番号やURLを指定するだけで、そのPRが適用された隔離セッションが起動します。
  • 手元の書きかけ環境を汚さない
    自分の作業中の変更をStashで退避したり、ブランチを破壊的にスイッチする必要は全くありません。
  • AIと共同で動作確認・検証
    隔離環境内で「このPRのテストを実行して」「変更箇所の懸念点をレビューして」とAIに指示しながら、安全に検証を進められます。

AGENT SETTINGサブエージェント用の隔離設定

  • サブエージェント定義（YAML）に記述
    サブエージェント定義ファイルのYAMLフロントマターに `isolation: worktree` を追記するだけで有効化されます。
  • 起動時に専用Worktreeを自動割当
    AIエージェントが起動されるたびに、システムがバックグラウンドで一時的なWorktreeと専用ブランチを自動生成します。
  • 複数AIの並列稼働によるファイル競合防止
    同じ作業ディレクトリの共有による上書き事故を100%防止し、各エージェントが異なるタスクを同時に実行できます。
agent-config.md ---
name: refactoring-expert
isolation: worktree
---

CLEANUP & ASSETS環境の維持とスマートな自動消滅

  • `.worktreeinclude` で環境引継ぎ
    `.gitignore`されている`.env`などの未追跡ファイルを指定しておくと、隔離環境に自動でコピーされます。
  • 「変更なし」なら跡形もなく自動消滅
    サブエージェントがコードの参照のみで一切変更を行わなかった場合、Worktreeのディレクトリとブランチは自動で削除されます。
  • 「変更あり」ならパスとブランチを報告
    編集やコミットが発生した場合は消去せず残し、「成果物はここです」と親エージェントや人間にパスを報告してくれます。

SUMMARYネイティブWorktree機能のまとめ

  • 開発者のための `--worktree` オプション
    Stashでの退避やブランチ移動の手間をなくし、別ブランチの作業や他人のPRレビューセッションをコマンド1つで安全に開始できます。
  • 自律AIのための `isolation: worktree`
    YAMLに1行追記するだけで、サブエージェントが自律的に専用ブランチを切り出して動くため、並列開発で競合が起きる心配がなくなります。
  • ライフサイクルのスマート自動化
    `.worktreeinclude` による未追跡ファイル自動引継ぎと、終了時の「変更なし➔自動削除」「変更あり➔パス報告」のクリーンアップにより運用コストゼロを実現。
