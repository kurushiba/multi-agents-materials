OVERVIEWカスタムサブエージェントとは？

  • 自分たち専用の「専門家」を定義
    汎用的な組み込みエージェントの枠を超え、チームのコーディング規約や独自のデプロイフローに最適化したエージェントを作れます。
  • シンプルな1ファイル構成
    設定情報となる「YAMLフロントマター」と、指示文である「システムプロンプト (Markdown)」の2つを1ファイルにまとめて定義します。
  • チーム間での共有が可能
    Gitリポジトリに含めて共有することで、すべての開発メンバーが同じカスタムエージェントを手軽に利用できます。
📄 code-reviewer.md
YAML 設定 ---
name: code-reviewer
description: チーム規約をレビューするエージェント...
tools: [Read, Grep]
---
System Prompt (指示本文) # Role
あなたは型安全とアクセシビリティの専門レビュアーです。以下の手順に従ってレビューを実施してください...

SCOPE2つの保存場所（スコープ）

  • プロジェクトスコープ (チーム共有向き)
    `.claude/agents/` に保存します。そのプロジェクト内でのみ有効で、コードベース固有の規約レビュー等に活用しGitで共有するのがベストです。
  • ユーザースコープ (個人利用向き)
    `~/.claude/agents/` に保存します。個人のPC上のすべてのプロジェクトから呼び出せる、自分専用の汎用アシスタントになります。
  • 同名時の優先順位（プロジェクト最優先）
    同じ名前のサブエージェントが両方に定義されている場合、プロジェクトスコープ側が優先して読み込まれます。

SETTINGSYAMLフロントマターと必須項目

  • 履歴書の「プロフィール欄」
    ファイルの先頭に `---` で挟んで記述する設定です。Claude Codeが本文（システムプロンプト）を読む前に確認する基本情報です。
  • name (必須)：一意の識別子
    小文字とハイフンで記述します。エージェントをチャットから直接呼び出すときのコマンド名（ID）として使われます。
  • description (必須・最重要)：自律委譲の鍵
    この説明文を読んで、Claude自身が「現在のタスクをこのエージェントに任せるべきか」を自律的に判断します。
code-reviewer.md
---
name:code-reviewer
# 🔑 最重要！この説明でAIが自動委譲を判断する
description:"コードの型安全性とアクセシビリティをチェックするための説明文。AIが「自動委譲」するかの判断に直結します。"
---
# ここからシステムプロンプト (Markdown本文)...

OPTIONS動作を制御する便利なオプション設定

  • tools / disallowedTools
    利用可能なツールを制限し、読み取りのみを許可するなどの安全なサンドボックス（制限環境）を構築できます。
  • permissionMode
    `acceptEdits`や`plan`といった承認確認モードを指定し、自律変更のルールを定めます。
  • maxTurns / model
    最大ループ回数を制限して暴走を防いだり、`haiku`や`opus`など用途に応じてコストと推論性能を最適化できます（省略時は親を継承）。

CREATION一番楽な作り方：Claudeに指示する

  • 手動でのフォルダ・ファイル作成は不要
    MarkdownやYAMLの書式、パスなどを覚える必要はありません。Claude Codeに指示をするだけで完成します。
  • 言葉で役割を伝えるだけ
    「アクセシビリティをチェックする読み取り専用のレビュアーを `.claude/agents/code-reviewer.md` に作って」と指示します。
  • 自動でYAMLとプロンプトを生成・保存
    適切な `description` や `tools` 制限をClaude自身が設計し、そのまま所定の位置へ自動保存してくれます。

SUMMARYカスタムエージェントのまとめ

  • 開発ルールを自動で守る仕組み
    チームの規約をカスタムエージェント化しGitで共有することで、コード品質の均一化を無理なく行えます。
  • YAML ＋ プロンプトの調和
    必須設定（name, description）のほか、モデルやツールの制限を組み合わせて自由自在にコントロール可能です。
  • 次回：descriptionの書き方比較
    自動委譲を大きく左右する `description` の役割。次回は「悪い例」と「良い例」を徹底的に比較していきます。
